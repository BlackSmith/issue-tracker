## Attachment Lifecycle

- Confirmed ticket attachments can be removed with `DELETE /api/v1/items/{item_id}/attachments/{attachment_id}` by ticket writers, including other uploaders' files. Original description/comment text is retained; historical links return 404. Description saves allow missing attachment IDs only when already present in that ticket's saved description, keeping later edits usable without accepting new expired references. ## API Tokens and Bot Accounts

- Migration `0004` adds `users.is_bot` (existing users default false) and `api_tokens` with separate owner/issuer IDs, a unique SHA-256 secret hash, display prefix, scopes, and integer UTC lifecycle timestamps. No token secret is stored in the database.
- Personal token management is at `/settings` and administrator-only bot management at `/admin/settings?tab=bots`. Credential management requires a browser session; bearer tokens cannot issue other credentials. Token scopes are independent of project roles, and current project access always limits token operations.
- Bearer authentication uses the token owner's current role and explicit project permissions, not browser cookies. A valid bearer request works with `credentials: 'omit'` and no CSRF header, returns no session cookie, and reports `auth_method: 'token'` with null CSRF in `/api/v1/auth/me`. Invalid Authorization does not fall back to a valid browser session. Read scope permits the read-only POST `/api/v1/references/resolve`.
- Bots are application members with explicit Reporter or Read-only project assignments; project-role changes immediately limit existing write-scoped tokens. Disabling a bot revokes all credentials, and re-enabling does not restore them. API-created comments retain the bot author and show a Bot badge even after the bot is disabled.
- Bot pictures are administrator-managed through `PUT`/`DELETE /api/v1/bots/{id}/avatar`, using the same normalized 256px PNG storage and validation as personal pictures. The Bot accounts list shows avatars, and its right panel provides upload/removal controls. Avatar reads preserve disabled bot attribution for authorized organization members, while inactive human pictures remain unavailable. Uploads do not reset unsaved bot name/role edits.
- Token secrets are available only at issuance, never in token lists. Do not log them or capture screenshots with the reveal open; revoke verification credentials afterward. On the HTTP development origin, `navigator.clipboard` is unavailable; the Copy fallback was verified using a CDP `Runtime.evaluate` call with `userGesture: true` (plain synthetic clicks do not establish clipboard user activation).
